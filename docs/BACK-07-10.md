# BACK-07 a BACK-10 — assistente local

Implementação isolada em `backend/app/assistant/`. A tela está em
`frontend/src/views/AssistantView.vue`, na rota `/assistente`.
Não cria usuários, migrações ou tabelas: esses itens continuam com BACK-01 a 06.

## Rodar com a equipe

1. Inicie Docker Desktop. No Windows/WSL, confira se há pelo menos 8 GB
   disponíveis para o WSL. Exemplo de `%UserProfile%/.wslconfig`:
   ```ini
   [wsl2]
   memory=8GB
   ```
   Aplique a configuração ao reiniciar o WSL/Docker; não sobrescreva outras
   configurações pessoais. Este trabalho não altera esse arquivo da máquina.
2. As migrações e o login dos BACKs 1 a 6 já estão integrados. Gere as credenciais
   locais com `python scripts/gerar_segredos.py`, conforme o guia de infraestrutura.
   O Compose mapeia `JWT_SECRET_KEY` do `.env` para `JWT_SECRET` na API e configura
   o PostgreSQL compartilhado automaticamente. `ASSISTANT_DATABASE_URL` é uma
   opção para execução local com banco separado, não um requisito do Compose.
3. Na raiz do projeto:
   ```powershell
   docker compose --env-file .env -f infra/docker-compose.yml --profile app up -d --build
   docker compose --env-file .env -f infra/docker-compose.yml logs -f ollama-init
   ```
   `ollama-init` baixa `llama3.2:3b` se ausente, faz uma chamada de aquecimento
   com o mesmo contexto de 8192 tokens da API e mantém o modelo na memória.
   A API espera esse serviço terminar com sucesso. Downloads exigem internet;
   a inferência depois disso é local. Faça o download antes da apresentação.
4. Mantenha `VITE_MOCK=false` no `.env` da raiz e refaça
   a subida com `--build` (é uma variável de compilação do frontend). Abra
   `http://localhost:8080/assistente`, com login real. Para Vite fora do Docker,
   configure também `frontend/.env`. O chat não inventa respostas no modo de demonstração.

Os modelos ficam no volume `ollama-models`. **Não execute `docker compose down -v`**
perto da apresentação: remove os volumes, inclusive modelos e bancos. `down`
sem `-v` preserva os modelos. Depois de reiniciar somente o Ollama, execute
novamente o init para reaquecer (`docker compose ... run --rm ollama-init`).

## Integração com BACK-01 a 06

- `app.main` inclui `app.assistant.router.router`. Se a API mudar de pacote,
  inclua esse router no novo aplicativo.
- Autenticação: reutiliza `app.ai_api.current_user`, a mesma dependência do
  login integrado (viewer, operator e admin podem perguntar).
- No lifespan, `app.state.assistant_db` recebe `app.core.pg.Database`.
  Por padrão, reutiliza `app.state.database`, criado pelo BACK-02. Uma URL
  `ASSISTANT_DATABASE_URL` explícita permite banco separado fora do Compose.
  Falha na auditoria retorna 503 antes de chamar o modelo.
- Usa reflexão das tabelas `audit`, `alerts` e `model_versions`, conforme
  `docs/ARQUITETURA.md` §16.1. Não modifica o schema. O evento de auditoria tem
  `type=assistant`, `action=question`, `username`, `ts`, `target=assistant`,
  `detail={question, reason}` e `ok` indicando aceitação da pergunta (não a
  qualidade ou conclusão da resposta). O BACK-06 deve permitir o tipo
  `assistant` no filtro da auditoria. Perguntas limitadas também são auditadas.
- Leituras: `app.state.repo` é o `InfluxRepository` existente. Usa os measurements
  `telemetry` e `insight` produzidos pelo Writer do segundo bimestre, últimas
  24 horas. Mantém horário por campo e ordena bombas pela menor saúde.
- Treino: usa `app.state.ai_store` se disponível (integração IA existente);
  senão lê `model_versions`. Resume versão, métricas e baseline, sem caminhos
  de arquivos ou credenciais. O resumo marca fontes indisponíveis explicitamente.
- O resumo é limitado; não afirma que listas truncadas representam toda a
  instalação. O modelo não recebe conexão, ferramenta ou acesso aos bancos.
- Limite móvel: 5 perguntas/60 s por `sub`. O limitador é **por processo**,
  adequado ao único worker do Dockerfile atual. Se a equipe adicionar réplicas
  ou múltiplos workers, deve compartilhar o contador antes de escalar. Reiniciar
  a API limpa essa janela em memória.

## Contrato HTTP

Todas as chamadas exigem `Authorization: Bearer <JWT>`.

- `GET /api/assistant/status`: `{ready, available, model}`. Consulta modelos
  carregados via `/api/ps`, não apenas modelos baixados. Não consome a cota.
- `POST /api/assistant`: `{"question":"Qual bomba precisa de atenção?"}`,
  texto não vazio, até 2000 caracteres. HTTP 429 inclui `Retry-After`.
  Streaming `application/x-ndjson`, uma linha por evento:
  ```json
  {"token":"A bomba "}
  {"token":"bomba-01…"}
  {"done":true}
  ```
  Em falha após iniciar a resposta: `{"error":"Resposta interrompida. Tente novamente."}`.
  Antes do streaming, falhas de Ollama/auditoria retornam 503. O frontend trata
  UTF-8 e linhas divididas entre chunks, cancelamento e streams incompletos.
  Cada pergunta é independente, com resumo atualizado; não envia histórico.
- Nginx desabilita buffering e cache no proxy e permite 300 s de leitura,
  preservando a entrega incremental pela porta 8080.
- Markdown: `html: false`, regra `image` desligada; HTML aparece escapado.

## Testes e comparação dos modelos

```powershell
.venv/Scripts/python.exe -m pytest backend/tests/test_assistant.py backend/tests/test_api.py -q -p no:cacheprovider
cd frontend
npm run build
node --experimental-strip-types tests/assistant-markdown.mjs
```

As oito perguntas e rubricas estão em `backend/app/assistant/questions.json`.
A cópia do frontend é verificada por teste para manter as sugestões iguais.
Sempre que alterar o prompt, rode ambas as avaliações abaixo e revise **cada
resposta** pela rubrica. A fixture é fixa e identificada como dado de teste;
não representa a situação real dos tanques. O comando imprime JSONL com
pergunta, rubrica e resposta; não declara aprovação automaticamente.

```powershell
docker compose --env-file .env -f infra/docker-compose.yml --profile app run --rm --no-deps ollama-init python -m tools.evaluate_assistant --url http://ollama:11434 --model llama3.2:3b
docker compose --env-file .env -f infra/docker-compose.yml exec ollama ollama pull qwen2.5:3b
docker compose --env-file .env -f infra/docker-compose.yml --profile app run --rm --no-deps ollama-init python -m tools.evaluate_assistant --url http://ollama:11434 --model qwen2.5:3b
```

Escolha o que acertar mais rubricas e responder melhor em português, registre
os resultados e coloque `OLLAMA_MODEL=<escolhido>` no `.env`. Recrie backend e
init com o comando de subida. O padrão permanece `llama3.2:3b` enquanto não
houver comparação real; não há alegação de vencedor sem ensaio.

Para conferir o streaming real via proxy, com um token válido:
```powershell
curl.exe -N http://localhost:8080/api/assistant -H "Authorization: Bearer $env:TANKVITALS_TOKEN" -H "Content-Type: application/json" --data-binary '@pergunta.json'
```
`pergunta.json` deve conter o corpo de exemplo acima. Compare a chegada dos
chunks; repetir seis vezes em menos de 60 s deve retornar 429 na sexta.

Limites da validação nesta implementação: testes locais usam Ollama simulado
e SQLite para verificar o contrato SQL. O ensaio com modelos reais, a porta
8080 e o PostgreSQL real aguardam Docker em execução. A integração de login,
assistente e auditoria é coberta por teste com o schema compartilhado em SQLite.
